# 김건우 · 개인 프로젝트 포트폴리오

인천전자마이스터고등학교 인공지능전자과 2학년 · innovation 팀원

기존 팀 프로젝트에서 백엔드·데이터 처리와 API·DB 설계 분야의 역할을 맡은 기획 경험을 정리했습니다. 이번 AgentBridge의 신청 분야는 AI·SW입니다.

## 1. 청주 안심동선 · 데이터 처리와 백엔드 설계 기획

**프로젝트:** 공공데이터로 고령보행자 위험지점과 도시안전시설 개선 우선순위를 제시하는 시스템을 기획했습니다. 팀원은 송지율·황재찬·김건우·송성재입니다.

**본인 역할의 근거:** 원본 제안서 17쪽에 김건우의 담당 분야가 “백엔드 / 데이터 처리”, 담당 내용이 “API·DB 설계, 데이터 정제, 보고서 출력 기능”으로 기록되어 있습니다.

이전 제안서에 기록된 개인 담당 역할과, 해당 역할에 연결되는 팀의 설계 산출물을 아래와 같이 정리했습니다.

| 담당 분야 | 제안서에 담긴 관련 설계 내용 | 원본 위치 |
|---|---|---|
| 데이터 정제 | 사고·인구·시설·도로 정보를 같은 100m 격자 단위로 결합 | 6·7쪽 |
| API·DB 설계 | 격자별 위험점수, 시설 정보, 개선 후보를 이어 주는 데이터 흐름 | 6·8쪽 |
| 보고서 출력 | TOP 20 지점·위험 원인·개선 근거를 정리한 보고서 구성 | 6·11쪽 |
| 구현 순서 | 수집·정제, 모델, 지도 시제품, 보고서로 이어지는 4주 계획 | 14쪽 |

**설계에서 다룬 문제:** 서로 다른 데이터의 위치와 단위가 맞지 않으면 위험도를 같은 기준으로 비교하기 어렵습니다. 팀 제안서는 100m 격자를 공통 단위로 삼고, 원천 데이터에서 지도와 보고서까지 정보가 어떻게 이어져야 하는지 정리했습니다.

**확인 가능한 산출물:** 제안서 PDF에는 데이터 목록, 결합 흐름, 위험도 출력, 화면 구성, 추진 계획과 개인별 역할이 남아 있습니다. 개인 담당은 이 역할표를 근거로 하며, 각 페이지 전체를 혼자 작성했다고 주장하지 않습니다.

**활동 범위:** 이 경험은 팀의 기획·설계 단계입니다. 실제 API 서버·DB·정제 파이프라인·보고서 생성기를 구현해 운영한 증빙은 현재 자료에 포함되어 있지 않습니다. 설계 경험과 구현 성과를 구분했습니다.

## 2. AgentBridge · AI·SW 분야 참여

2026년 9월 3일 제출된 팀 개발기획서에 AI·SW 분야 팀원으로 기재되어 있습니다. AI 에이전트 선택과 설치에 어려움을 겪는 사용자를 위해 추천·설치 가이드·데모를 제공하는 프로젝트입니다.

팀 전체의 소스에는 도구 데이터, TF-IDF·코사인 유사도 기반 추천, 운영체제별 설치 단계, 로컬 데모가 포함되어 있습니다. 제출 신청서에는 김건우 개인의 파일·함수 단위 분담까지 기록되어 있지 않으므로, 이 항목은 신청 분야와 팀 참여 사실을 중심으로 작성했습니다.

증빙: [AgentBridge 자료](../projects/agentbridge.md), [기존 출품작 ZIP](../AgentBridge_project.zip)

## 경험에서 확인할 역량

| 영역 | 현재 자료가 보여 주는 내용 |
|---|---|
| 데이터 구조에 대한 기획 | 여러 원천 데이터를 공통 공간 단위로 결합하는 팀 설계 참여 |
| 백엔드 역할 이해 | 데이터 입력·처리·출력과 API·DB 역할의 연결 |
| 협업 범위 설정 | 모델·지도·기획 담당과 구분된 백엔드·데이터 분야 역할 |
| 결과물 설계 | 점수만 나열하지 않고 원인·개선 근거가 포함된 보고서 구성 |

개인 개발 역량의 근거는 현재 확보한 설계 제안과 담당 역할까지이며, 별도의 개인 코드·수상·자격 이력을 임의로 추가하지 않았습니다.
